# Feature 6 — 條目介面即時搜尋

> 搜尋規格已由使用者確認；本文件作為 scope/acceptance commit，先開 draft PR，再開始 production-code 修改。

**Goal:** 在已解鎖的「條目」分頁提供即時搜尋，讓使用者依網站、帳號或備註快速篩選金庫條目。

**Architecture:** 前端以已載入的條目資料在記憶體中篩選；不新增 Tauri command、網路呼叫、儲存欄位或金庫格式變更。

## 已確認行為規格

- 搜尋範圍僅限「條目」分頁，不搜尋金鑰管理或軌跡紀錄。
- 搜尋欄位為 `site`（網站）、`account`（帳號）及 `notes`（備註）；以不區分大小寫的部分文字比對。
- 不搜尋目前密碼或任何舊密碼歷史。搜尋邏輯不得讀取或比對這些欄位。
- 只在金庫解鎖後顯示及使用搜尋；以現有已載入條目在前端記憶體篩選，不逐次呼叫後端。
- 搜尋為即時篩選；清除查詢即恢復完整條目清單。空白／只有空白字元的查詢視為未套用篩選。
- 顯示符合筆數；零筆時明確顯示「沒有符合搜尋條件」，並與金庫本來沒有條目的狀態區分。
- 篩選只改變清單呈現，不改動資料；新增、編輯、刪除或 CSV 匯入後重新載入清單時，仍套用目前查詢。清單列上的顯示、複製、編輯、刪除動作必須仍作用於正確條目。
- 搜尋欄需有可存取名稱與結果狀態提示；不把查詢內容寫入 audit、診斷 log、檔案或持久化設定。不得把使用者查詢字串當 HTML 插入 DOM。
- 不包含跨分頁／全域搜尋、密碼搜尋、舊密碼歷史搜尋、正規表示式、搜尋結果排序、分頁或搜尋歷史。

## 預計修改範圍

- `src/index.html`、`src/app.js`、`src/styles.css`：條目搜尋欄、純前端篩選、結果筆數／空狀態及基本可存取性。
- Node UI 測試：可新增 `tests/entry-search-ui.test.cjs`，覆蓋欄位範圍、比對、清除、空狀態及條目動作；需要時更新既有 UI 測試。
- `README.md`、`docs/user-verification-steps.md`：記載功能及 Win11-NB 本機 Console 驗收步驟。
- 不修改 Rust 後端、Tauri command、vault payload/schema 或加密流程，除非實作時發現目前架構無法滿足已確認規格；如需擴大範圍，先向使用者確認。
